# WellPadOptimizer 2 — кустование скважин и расчёт траекторий (C#, .NET 8)

Распределяет скважины по кустам, находит точки устьев, рассчитывает траектории с технологическими ограничениями
и минимизирует затраты на бурение, строительство кустов и отсыпку с учётом карты желательности местности.

## Состав решения

```
WellPadOptimizer.sln
src/WellPadOptimizer.Core   вычислительное ядро (библиотека): карта, траектории, оптимизация, отчёты
src/WellPadOptimizer.Cli    консольная программа WellPadOptimizer(.exe)
src/WellPadOptimizer.Gui    программа с графическим интерфейсом WellPadOptimizerGui.exe (Windows, WPF)
settings.json               параметры расчёта
data/input_mass.json        пример входных данных
data/kin_map_example.bin    пример карты желательности в формате КИН
data/terrain_map_example.asc синтетическая карта ESRI ASCII (для проверки)
data/existing_wells_example.csv синтетические существующие скважины (инклинометрия) для проверки антистолкновения
assets/                     сюда при сборке скачивается plotly.min.js (встраивается в report.html)
```

## Графический интерфейс (WellPadOptimizerGui.exe)

* **Данные** — входной файл, файл настроек (загрузить / сохранить), папка результатов.
* **Карта** — выбор источника карты желательности (см. ниже), таблица соответствия значений КИН,
  слои OpenStreetMap, таблица классов местности (высота отсыпки, доп. затраты, запрет),
  кнопка «Построить карту (предпросмотр)».
* **Параметры** — ограничения, размеры и стоимость кустов, параметры оптимизации и нагрузок.
* Справа: журнал расчёта, план с картой и траекториями (Ctrl + колесо — масштаб), 3D-сцена
  (вращение мышью), таблицы вариантов, кустов и скважин; кнопки «Открыть отчёт» и «Папка результатов».

## Входные данные: три формата

* `input_mass.json` (rndrilling-v3): цели T1/T3 = [North, East, TVD] в UTM, варианты с заданными устьями.
* **Проект кустования КИН** (`*.json` с разделами `props`, `wrappers`, `assets`):
  * цели — `props.Wells[].Rating[0].Hor.Trajectory.Points` (концы ГС в градусах WGS 84), глубина — `WellBottom.Depth`;
    координаты переводятся в UTM зоны центра участка;
  * варианты кустования КИН (`wrappers`) — пересчитываются по модели программы и попадают в сравнение
    как «Вариант КИН N» (устья — `WellHeadUTM`);
  * карта желательности, встроенная в проект (`assets`, файл из `TopologyMap`), используется без отдельного файла;
  * параметры проекта (`props`) переносятся в расчёт: в интерфейсе флажок «взять параметры и карту из проекта»,
    в консоли ключ `--project-settings`.
  * в проектах КИН начало ГС выбирается расчётом, поэтому горизонтальный участок может буриться с любого конца
    (`ReverseHorizontal` = `Auto`; `Always` — для всех целей, `Never` — строго T1→T3).

* **Таблица скважин Excel (.xlsx) или CSV** — например, выгрузка слоя проектных скважин. Первая строка — заголовки:
  «Имя»; начало ГС «X», «Y» (или «X1», «Y1»); конец ГС «X2», «Y2» (или «Xзаб», «Yзаб», или «Азимут» + «Длина»);
  глубина «Глубина» / «TVD» / «Z» — если её нет, берётся `DefaultTargetTvd`. Остальные столбцы игнорируются.
  Координаты (`TableCrs` = `Auto`): градусы WGS 84; СК-42 Гаусса–Крюгера, если в восточной координате есть номер зоны
  (12 601 924 → зона 12) — с пересчётом в WGS 84 по ГОСТ 32453-2017 (`TableDatumShift`); иначе UTM (`ProjectedCrs`),
  а без проекции — местные координаты (расчёт без карт КИН и OSM). Примеры: `data/wells_example.xlsx`, `data/wells_example.csv`.

## Z-кусты (два направления движения станка, 2 НДС)

`PadLayout`: `Single` — однорядный куст (1 НДС); `Z` — кусты от `ZMinWells` скважин строятся как Z-кусты:
два параллельных ряда устьев на расстоянии `ZRowSpacing`, станки движутся встречно (НДС 2 = НДС 1 + 180°),
ряды можно сместить вдоль НДС на `ZRowShift`; `Auto` — для каждого куста выбирается схема с меньшими затратами.
Площадка Z-куста короче и шире (длина по большему ряду, ширина `PadWidth + ZRowSpacing`); отсыпка считается по
её фактическому контуру. `ZPadBuildCostFactor` — коэффициент стоимости строительства, `ZPadSavingPerWell` — эффект
одновременного бурения двумя станками на скважину (сокращение сроков), тыс. руб. При `PadLayout` = `Single` и
`CompareZLayout` = true программа дополнительно считает сценарий с Z-кустами для сравнения.
В таблицах кустов выводятся схема и азимуты НДС.

## Антистолкновение и существующие скважины

Проверяется сближение стволов по всей длине: проектных скважин между собой (в одном кусте и в соседних) и каждой
проектной скважины с существующими. Модель неопределённости — шар радиусом r(MD) = `AcSurfaceError` + `AcErrorPerKm`·MD/1000
(по умолчанию 0,5 м + 6 м на 1000 м). Коэффициент разделения SF = D / (r₁ + r₂), D — расстояние между осями стволов
(ближайшее сближение «точка — отрезок»).

* SF < `AcMinSF` (1,5) — нарушение «антистолкновение»; SF < `AcWarnSF` (2,0) — предупреждение «сближение».
* В оптимизации сближение с существующими скважинами входит в матрицу «площадка × скважина» (штраф `PenaltyViolation` +
  `PenaltyAntiCollision` за недостающую единицу SF; точки траектории через `AcOptimizationStep` = 30 м).
* При раскладке скважин по слотам куста учитывается SF между стволами куста до `AntiCollisionMaxMD`.
* При пересчёте варианта — точная проверка всех пар и существующих скважин; в таблице скважин — «Мин. SF» и «Сближение с».
* `AntiCollisionCheck` = false отключает проверку.

**Существующие скважины** (`UseExistingWells` = true):
* раздел `trajRealWells` входного файла input_mass.json — учитывается автоматически;
* файл `ExistingWellsFile` (в интерфейсе — вкладка «Данные», в консоли — `--existing`):
  * JSON в формате `trajRealWells` (устье `CoordsX`/`CoordsY`, смещения `X`/`Y`, `AbsoluteDepth`, `MeasuredDepth`);
  * Excel / CSV с точками траектории: «Скважина», «X», «Y», «Z» (или «TVD», «Абс. глубина»; «Абс. отметка» — высота,
    знак меняется), необязательно «MD»;
  * Excel / CSV с инклинометрией: «Скважина», «MD», «Зенит», «Азимут», устье «Xустья», «Yустья» (или «X», «Y»),
    необязательно «Альтитуда» (тогда Z = TVD − альтитуда, абсолютная глубина) — расчёт методом минимальной кривизны.
  Координаты — в метрах проекции расчёта, в градусах WGS 84 или в СК-42 Гаусса–Крюгера с номером зоны.
* Глубины существующих скважин должны быть в той же системе, что и глубины целей; поправка — `ExistingWellsZShift`.

## Режим учёта ограничений (`ConstraintMode`)

| Значение | Поведение |
|---|---|
| `Soft` (по умолчанию) | нарушения отхода, мин. отхода до T1, разворота, MD и антистолкновения допускаются со штрафом, если иначе решения нет; сначала минимизируется число нарушений |
| `Hard` | каждое нарушение получает максимальный штраф `PenaltyHard` (10¹² тыс. руб.), а решения, в которых нарушение всё же осталось, отбраковываются. Если разбить скважины на кусты без нарушений нельзя — «нет решения» с перечнем скважин, у которых нет ни одного устья без нарушений |
| `Both` | основной расчёт со штрафами и дополнительный сценарий «жёсткие ограничения» для сравнения |

Ограничения, которые проверяются только при пересчёте варианта (сближение стволов одного куста, нагрузка на крюке,
момент, отход от конкретного слота), в жёстком режиме тоже минимизируются при раскладке, но могут остаться —
тогда в журнале выводится предупреждение.
Сближение проектных стволов между собой на глубине зависит от состава куста и в матрицу «площадка × скважина» не входит:
оно находится при пересчёте варианта и учитывается при выборе рекомендуемого (минимум нарушений), но жёсткий режим его не исключает.

## Карта желательности — три источника (параметр `MapSource`)

| MapSource | Источник | Что нужно |
|---|---|---|
| `None` | **Без карты.** Вся поверхность — суходол (`DefaultTerrainCode` = 1), запретных зон нет | ничего |
| `Kin` | **Карта в формате КИН** (.bin) | `MapFile` — путь к файлу |
| `Osm` | **Открытые источники — OpenStreetMap**: болота, реки и озёра, кедровники, лес, природоохранные территории, застройка | интернет (Overpass API) или файл GeoJSON / сохранённый ответ Overpass (`OsmMode` = `File`, `MapFile`) |
| `Asc` | Растр ESRI ASCII Grid в проекции скважин | `MapFile` |

Если файл карты не найден, расчёт идёт без карты (суходол) с предупреждением в журнале.

### Формат КИН (.bin)

Сетка в градусах WGS 84: заголовок (число строк и столбцов, границы по долготе и широте), блок значений float32
по строкам, подпись слоя. Значения переводятся в классы программы таблицей `KinCodes`
(по умолчанию 2 — суходол, 3 — болото, 4 — водоём). Ячейки без данных и область вне карты — запретная зона
(`KinNoDataForbidden`). Строки идут от южного края (`KinRowsFromSouth` = true); если на предпросмотре реки
оказываются не на своих местах, снимите этот флажок. Карта пересчитывается в растр UTM с шагом `MapCellSize`.

### OpenStreetMap

Запрос к Overpass API строится по границам участка; ответ сохраняется в `results/osm_overpass.json` и может
использоваться повторно без интернета (`OsmMode` = `File`). Классы и приоритет наложения:

| Слой OSM | Теги | Класс |
|---|---|---|
| ООПТ, заповедники, нацпарки | `boundary=protected_area / national_park`, `leisure=nature_reserve` | запрет |
| Застройка, промзоны, кладбища | `landuse=residential / industrial / commercial / cemetery / military / quarry` | запрет |
| Водоёмы | `natural=water`, `waterway=riverbank`, `landuse=reservoir` | 3 — водоём |
| Реки, каналы, ручьи | `waterway=river / canal / stream / ditch / drain` (ширина — тег `width` или `RiverWidth`…) | 3 — водоём |
| Болота | `natural=wetland` | 2 — болото |
| Кедровники | лес, в тегах которого есть «кедр», *Pinus sibirica* | 4 — кедровник |
| Прочий лес | `landuse=forest`, `natural=wood` | 5 — лес |

`WaterProtectionBuffer` > 0 добавляет запретную водоохранную полосу. В GeoJSON можно задать класс
объекта напрямую свойством `wpo_class`; координаты — в градусах WGS 84 или в метрах проекции скважин
(так можно использовать слои из QGIS / NextGIS).

### Классы местности (`Terrain`)

Для каждого класса: высота отсыпки (м), дополнительные затраты на площадь куста (тыс. руб./га —
компенсации за вырубку, рекультивацию) и признак запрета. По умолчанию: суходол 1 м, болото 2,5 м,
водоём 4 м, кедровник 1 м + 1500 тыс. руб./га, лес 1 м + 300 тыс. руб./га.

## Консольная программа

```
WellPadOptimizer --input data/input_mass.json [--settings settings.json] [--out results]
                 [--map-source None|Kin|Osm|Asc] [--map файл] [--osm-mode Overpass|File]
                 [--pad-layout Single|Z|Auto] [--project-settings] [--synthetic-map] [--no-pause]
                 [--existing файл] [--constraints Soft|Hard|Both] [--no-anticollision] [--no-existing]
```

Окно не закрывается после расчёта (нажмите любую клавишу); `--no-pause` отключает ожидание.

## Модель и алгоритм

Целевая функция (тыс. руб.): Σ кусты [строительство(n) + отсыпка и доп. затраты по карте] + Σ скважины [65·MD до T1 + 55·L(T1–T3)].

* Профиль: вертикаль → набор R1 → тангенс → набор/разворот R2 с выходом в T1 по направлению T1→T3 → ГС.
* Размер куста — жёсткое ограничение `MinWellsPerPad` ≤ n ≤ K. Технологические ограничения (отход, мин. отход до T1, разворот, MD, антистолкновение)
  при невозможности их выполнить нарушаются со штрафом (в режиме `Hard` — не допускаются): сначала минимизируется число нарушений, затем затраты.
* `MinOffsetT1` (по умолчанию 200 м) — минимальный горизонтальный отход точки T1 от устья для горизонтальных скважин:
  исключает бурение ГС «под куст». Проверяется в матрице стоимостей (штраф `PenaltyViolation` +
  `PenaltyMinOffsetPerM` за каждый недостающий метр), при раскладке скважин по слотам (сначала минимизируется
  число нарушений) и при итоговой проверке — нарушение «мин. отход». Для скважин без ГС (T1 = T3) не применяется;
  при бурении ГС с обратного конца проверяется отход до фактического начала ГС. 0 — проверка отключена.
* Кусты не размещаются на запретных классах; отсыпка считается по долям классов под площадкой.
* Скважины делятся на группы; для каждой перебирается число кустов, разбиение k-средних и локальный поиск.
* Нагрузка на крюке и момент — «мягкая» модель Johancsik; антистолкновение по коэффициенту разделения SF (см. выше).

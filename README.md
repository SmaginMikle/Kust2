# WellPadOptimizer — кустование скважин и расчёт траекторий (C#, .NET 8)

## Запуск

```
dotnet run -c Release -- --input data/input_mass.json --map data/terrain_map.asc --settings settings.json --out results
```

Если файл карты не найден, программа строит синтетическую карту и сохраняет её в `results/terrain_map_synthetic.asc`.
Внешних пакетов NuGet нет: используются только System.Text.Json и Parallel.

## Сборка в GitHub и релизы

* `.github/workflows/build.yml` — при каждом push/pull request: сборка, проверочный расчёт на `data/input_mass.json`,
  результаты (`report.html`, CSV) сохраняются в артефакт `ci-results` на 14 дней.
* `.github/workflows/release.yml` — при push тега `v*` (или вручную через Actions → release → Run workflow):
  автономные однофайловые сборки для `win-x64`, `linux-x64`, `osx-arm64` (.NET устанавливать не нужно),
  проверочный запуск, архивы `WellPadOptimizer-<тег>-<платформа>.zip` с исполняемым файлом, `settings.json`,
  `README.md` и папкой `data/` прикладываются к релизу GitHub.

Выпуск релиза:

```
git tag v1.0.0
git push origin v1.0.0
```

Запуск из релиза (Windows): `WellPadOptimizer.exe --input data\input_mass.json --out results`.

## Входные данные

* `input_mass.json` (формат rndrilling-v3). Цели берутся из `massiveDataVariants[].trajBuildRequest[]`:
  `T1`/`T3` = [North, East, TVD]. Варианты из файла с заданными устьями (`wh_north`, `wh_east`, `pad_id`)
  считаются по той же модели затрат и попадают в сравнение как «Исходный вариант N».
* Карта желательности — ESRI ASCII Grid (`.asc`) в той же проекции (EPSG 32642).
  Коды классов: 1 — суходол, 2 — болото, 3 — водоём, 9 — запрещено; NODATA и точки вне карты тоже запрещены.
  Высота отсыпки по классам задаётся в `settings.json` (по умолчанию 1,0 / 2,5 / 4,0 м).
* `settings.json` — параметры окна настроек (отход 1500 м, MD 4000 м, темпы 0,5 и 1,5 °/10 м,
  вертикаль 40 м, разворот ≤ 90°, крюк 180 тс, момент 54 кН·м, стоимости ННС/ГС/кустов/песка, перебор 10–24 скв.).

## Модель и алгоритм

**Целевая функция** (тыс. руб.):
Σ по кустам [строительство(n) + отсыпка(место, n)] + Σ по скважинам [65·MD(устье→T1) + 55·L(T1→T3)].

* Строительство: n ≤ 12 — 16 000 на скважину, 13–19 — 13 000, 20–24 — 12 000.
* Отсыпка: площадка W × L (L = длина ряда устьев + 2·60 м; устья группами по 4, 6 м в группе, 15 м между группами).
  Объём = Σ доля_класса · h·(L + m·h)·(W + m·h), откос 1:1,5. Доли классов считаются по точкам площадки с шагом 10 м;
  если хотя бы одна точка (с учётом буфера) попадает в запретную зону, ориентация недопустима. Перебираются 6 ориентаций.

**Профиль скважины** (`Trajectory.cs`): вертикаль 40 м → набор R1 = 10/(0,5°) ≈ 1146 м → тангенс → набор/разворот
R2 ≈ 382 м с выходом в T1 точно по направлению T1→T3 → горизонтальный участок. Направление тангенса d находится
итерацией неподвижной точки: d = норм(P2(d) − P1(d)), где P1 и P2 — концы дуг по методу минимальной кривизны.
Для целей с T1 = T3 строится J-профиль. Инклинометрия выводится с шагом 10 м.

**Ограничения** (для пары устье–цель): отход до T1 ≤ MaxOffset; разворот (угол между азимутом «устье→T1» и азимутом T1→T3)
≤ MaxAzimuthTurn; существование профиля при заданных темпах; MD до T1 ≤ MaxMD
(флаг «На забой» = `LimitsToBottomHole` переносит ограничения на T3). Нагрузка на крюке и момент считаются
«мягкой» моделью Johancsik (127 мм БТ, коэффициенты трения 0,25 и 0,30) и проверяются в итоговой оценке.

**Оптимизация** (`Optimizer.cs`):
1. Кандидатные площадки — сетка 100 м в радиусе MaxOffset от T1.
2. Матрица стоимости бурения «площадка × скважина» (∞ при нарушении ограничений), параллельно.
3. Таблица отсыпки «площадка × число скважин» по карте.
4. Жадная инициализация: куст с минимальной средней стоимостью на скважину.
5. Локальный поиск: перенос скважины, обмен скважинами, перенос площадки, закрытие куста.
6. Раскладка скважин по слотам (`Evaluator.cs`): перестановки, максимизирующие минимальное сближение стволов.

**Набор вариантов для сравнения**: исходные варианты из файла; перебор макс. числа скважин на кусте
(Start…End с шагом VariantStep); тот же перебор без ограничения разворота; варианты с лимитом числа кустов
(кривая «число кустов — затраты»). Варианты с одинаковым составом кустов помечаются «совпадает с…».

## Результаты (`--out`)

| Файл | Содержимое |
|---|---|
| `report.html` | 3D-траектории над картой, план с картой желательности, проекции на вертикальные плоскости N–TVD и E–TVD, таблицы кустов и скважин, сравнение всех вариантов и попарное сравнение A/B |
| `summary.csv` | сводка по вариантам: кусты, ΣMD, затраты по статьям, нарушения |
| `pads.csv` | кусты: координаты, ориентация, доли местности, объём и стоимость отсыпки |
| `wells.csv` | скважины: устье, отход, разворот, MD, тангенс, нагрузки, сближение, стоимость, нарушения |
| `trajectories/variant_NN.csv` | инклинометрия (MD, зенит, азимут, N, E, TVD, ПИ) |
| `results.json` | данные для визуализации |

CSV — разделитель «;», десятичная запятая, UTF-8 с BOM (открываются в Excel).

## Структура

```
src/Parameters.cs   параметры, функции стоимости, геометрия площадки
src/InputData.cs    чтение input_mass.json
src/Terrain.cs      карта желательности (.asc), синтетическая карта
src/Trajectory.cs   профиль, инклинометрия, нагрузка на крюке и момент
src/Optimizer.cs    площадки-кандидаты, матрицы затрат, жадный алгоритм + локальный поиск
src/Evaluator.cs    итоговый расчёт варианта, раскладка по слотам, антиколлизия
src/Reporting.cs    консоль, CSV, JSON, HTML
report_template.html  шаблон отчёта (Plotly), встраивается в сборку
```
